# Attended Home PC relay activation

Use this procedure after a separately authorized attended maintenance window. The current production relay remains the remote connection until the owner can recover it locally.

1. Identify the current launcher, Windows user, working directory, known-good checkout, registered device in Operations and existing scheduled tasks. Record the current PID and launcher without printing command-line credentials. Keep the launcher and existing device registration available for rollback. The candidate supervisor task runs at interactive logon for that Windows user.
2. Prepare the exact tested backend and worker revisions. Keep C: development and D: workshop roots and the existing media root. Keep the same Windows account and stored Codex sign-in. Do not copy, print, reset, rotate, or re-register credentials.
3. From the candidate checkout, run `Start Crossworld Operations.cmd --check` and then `Start Crossworld Operations.cmd --check-device` using the original Windows account. The device readiness request does not acquire a worker lease. Check that the version-matched backend supports the probe before interpreting a 404. Verify that the configured worker can authenticate without opening a login prompt.
4. In the attended window hold future dispatch and let claimed turns finish. Check every host slot, finishing status and in-flight media transfer before stopping the identified launcher. Preserve its checkout and configuration. Confirm the process has ended before starting a replacement.
5. Run `Register-SupervisorTask.ps1 -WhatIf` to inspect the intended logon registration. After verifying the Windows user and target checkout, register the task once with confirmation and start only that task. The supervisor starts the worker as a child and owns its restart cycle.
6. Verify the same registered Home PC comes back online with the expected heartbeat and check `%LOCALAPPDATA%\Crossworld Operations\supervisor.jsonl` for startup and readiness. Inspect relay version, advertised permissions, model and reasoning support, employee conversation and review slot capabilities, media capabilities and available capacity. Advertised features still need a real smoke test.
7. Reopen dispatch under owner control. Use small disposable read-only executions to verify conversation, continuation, result and report attribution. Verify only the collaborator features present in the candidate. Test media using an authorized fixture. Before attempting a restart or logon test, finish those runs and verify the owner has a functioning recovery path. A remotely controlled restart is available only if an independently verified and production-enabled operation explicitly provides it.
8. On failed startup, stop the candidate supervisor first so it cannot relaunch its child. Disable its logon task, restore the prior launcher and start it using the original account and device registration. Verify existing device heartbeat, dispatch and a read-only smoke test. Record the reason and preserve supervisor logs.

Disposable tests verify crash recovery, repeated-start failure limits and graceful draining. Production unattended sign-in, replacement, remote restart and rollback require attended confirmation.
